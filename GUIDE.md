# Инструкция v0.2.6

## Что запускается

Windows запускает штатный PowerShell/OpenSSH, macOS — штатный bash/OpenSSH. Локальный Python, Git-клиент, клонирование, распаковка и локальные шаблоны не нужны. Короткий запускающий текст выполняется в памяти терминала. Временный SSH-config (а на macOS также FIFO и сообщения ошибок транспорта) генерируется локально и удаляется при завершении; это не скачанный комплект программы. Новые SSH-ключи и known_hosts остаются на компьютере по явному выбору пользователя.

Полный комплект v0.2.6 скачивают **сами обе VPS** из Git, сверяют закреплённый SHA256 и исполняют в памяти. Общий диалог и координация — `controller.py` на входной VPS; конфигурации — `render.py`; применение и откат обеих ролей — один `remote.py`. `client.py` сохраняет общие тексты вопросов и инструменты локальных тестов разработчика; его прежний локальный orchestration-путь в пользовательском запуске не используется.

Диалог идёт в исходном терминале через `ssh -tt`. Чтобы не передавать SSH-ключи или ssh-agent на сервер, запускающий код держит два SSH-соединения и соединяет серверные части через локальный и обратный TCP-туннели. RPC выхода слушает только127.0.0.1, требует случайный сеансовый токен, прекращает работу при штатном закрытии или через2часа. Токен и необязательный импорт передаются зашифрованными SSH environment requests (`LC_EVPN_*`), без аргументов командной строки и файлов с токеном. Клиентские пароли не передаются выходной VDS.

Поддерживаемая ОС серверов — Ubuntu 24.04/26.04 amd64/systemd, root. Нужны обычные для чистой Ubuntu настройки OpenSSH: `AcceptEnv LANG LC_*` и разрешённое TCP forwarding. Проверка LC_* выполняется экспериментально до загрузки кода; туннели создаются с ExitOnForwardFailure. Эти настройки установщик автоматически не ослабляет. Если образ был специально ограничен, проверьте `sshd -T` через консоль провайдера; изменение SSH требует отдельного решения. Облачный firewall должен пропускать SSH, затем TCP80/443 входа и UDP-порт Q12 выхода от IP входа. Панель провайдера установщик не изменяет.

**B01** — при отсутствии Windows OpenSSH Client предлагается установить системный компонент Microsoft, с UAC. На macOS используются предустановленные ssh/curl/openssl/base64. Python нужен только на VPS; если его нет в минимальном образе, Q22 отдельно предлагает установку после проверки платформы. Внешний первый запуск доверяет HTTPS GitHub; SHA256 серверного комплекта встроен в закреплённый загрузчик.

## Вопросы мастера

Серверные ответы можно исправить на Q20: введите обозначение вопроса. Локальные SSH-параметры задаются до соединения; для их изменения перезапустите ту же команду. Невалидная конфигурация не допускается к SSH/установке. Пути допускают пробелы и Unicode, `~` означает домашнюю папку; укажите путь без внешних кавычек.

| ID | Назначение, источник сведений, ответы и последствия |
|---|---|
| Q00 | Меню на входной VDS: `new` — новая конфигурация; `apply-saved` — повтор с сохранёнными параметрами; `preview` — просмотр; `verify`, `rollback`, `acceptance`, `reboot-test` — проверка/откат. Для сохранённой конфигурации запрашивается Q02. Рекомендуется `new` для первой установки. |
| Q01 | Режим. `fresh`: две чистые VDS. `replace-entry`: новый вход и сохранённый выход, рекомендуется для первой приёмки. `replace-exit`: сохранённый вход и новый выход. Старую ноду установщик не удаляет. |
| Q02 | Постоянный ID, 3–10 строчных латинских букв/цифр, первая буква. Выберите, например, `personal`. При повторе тот же ID: так находятся прежние ключи и журнал. Для параллельного legacy-переноса используйте новый ID. |
| Q03 | `root@IP` нового/сохранённого входа или SSH alias из `~/.ssh/config`. Источник — панель VDS. Alias раскрывается локально; параметры старого ProxyJump не принимаются за доказательство прямой доступности. |
| Q04 | Публичный IPv4 входа из панели. Не hostname. Именно эта VDS будет принимать HTTPS. |
| Q05 | Для SSH-алиаса мастер также использует первый настроенный IdentityFile, если файл существует.  `root@IP` или SSH alias выхода. При первой миграции — существующий `hosth-exit`. |
| Q06 | Публичный IPv4 выхода; он должен совпасть с TCP/STUN-результатами. Выход через дополнительный NAT с другим публичным адресом в v1 не поддержан. |
| Q07 | ASCII-домен, которым вы управляете. Для испытания рекомендуется новый поддомен с A-записью на новый вход. AAAA удалите, пока IPv6 не обслуживается. DNS меняется вручную и отдельно; доступ TCP80/443 нужен ACME. |
| Q08 | `legacy`: сохранённая нода проверенной схемы проекта с personal-vpn, personal_host и ключом `/etc/wireguard/personal.key`. `managed`: нода этого установщика с тем же ID. В fresh ответ игнорируется. Неизвестный legacy-формат отклоняется. |

Рекомендуется действующий административный ключ; `new` создаёт Ed25519 в `~/.ssh/empire-install`, без перезаписи существующей пары. ssh-keygen дважды спрашивает необязательную парольную фразу. |
| Q10 | Отдельная RFC1918 IPv4-подсеть `/30`. По умолчанию `10.203.71.0/30`. Для нового входа с legacy-выходом нужна новая непересекающаяся подсеть. Для замены legacy-выхода укажите прежнюю WG-подсеть входа: агент проверит её. |
| Q11 | Подсеть `/30` для реле хост↔namespace, по умолчанию `10.203.72.0/30`. Не пересекается с Q10 и маршрутами хостов. Для сохранённого legacy-входа существующее реле не меняется. |
| Q12 | Свободный UDP-порт выхода, 1024–65535, рекомендуется 51830 для параллельного туннеля. Открывается на сервере только для публичного IP входа; ACL панели провайдера задаётся отдельно. |
| Q13 | Необязательный путь к экспорту `empire-vpn-clients` версии1 вне репозитория. Импорт сохраняет все логины/пароли. Локальный вопрос перед SSH-диалогом. Пустой ответ использует сохранённый на входной VDS экспорт либо Q14. Содержимое импорта передаётся только входной VDS. Архив rootfs сюда не подходит. |
| Q14 | Логин при создании нового клиента, 1–64 символа `A-Z a-z 0-9 _ . @ -`, рекомендуется `owner`. **Q14-P** после APPLY: скрытый пароль или пусто для случайного. При повторе пароль не спрашивается и не меняется. |
| Q15 | Дополнительные защищённые IPv4 через запятую, например резервная VDS. Запрещены как цели установки и как направления прокси. Можно пусто. Вход/выход автоматически запрещаются как направления прокси. |
| Q16 | `ready`: DNS уже направлен на новый вход; перед фиксацией обязательны HTTPS/TCP/UoT. `defer`: зафиксировать рабочую изолированную сеть после проверки ожидаемого egress, TLS/клиентскую приёмку выполнить позже. `defer` не считается полной приёмкой. |
| Q17 | При ошибке авторизации: `retry` — загрузить ключ в ssh-agent и повторить; `password` — OpenSSH скрыто спрашивает пароль и добавляет только публичный ключ; `console` — команда для консоли провайдера. | Q18 | Как компьютеру подключиться к указанному серверу по SSH, если прямое соединение не удалось? **1** — через сервер из ваших SSH-настроек (мастер покажет имя). **2** — через вторую VDS этой установки, если прямой вход на неё уже проверен (мастер покажет адрес). **0** — остановить мастер. Если выбранный маршрут недоступен по сети, мастер возвращается к Q18 и сохраняет введённые ответы. Enter выбирает номер в квадратных скобках. Для переноса со старого входа обычно подходит 1. При установке с нуля без настроенного перехода выбирайте 2, если он предложен. Выбор касается административного SSH-подключения. |
| Q19 | Посмотрите параметры, список создаваемых/обновляемых файлов, пакеты и ограничения отката. Только точное `APPLY` разрешает установку. Иной ответ останавливает работу. |
| Q20 | `continue` подтверждает ответы; `Qxx` позволяет изменить ответ. После исправления снова проверяются все параметры. |
| Q21 | При защищённом ключе и отсутствии агента `yes` запускает ssh-agent (Windows: UAC/служба; macOS: агент с окружением текущего процесса). `no` останавливает. ssh-add скрыто спрашивает парольную фразу; она не хранится. |
| Q22 | Только если минимальный образ VDS не содержит python3: `INSTALL-PYTHON` отдельно разрешает apt-get update/install python3 для инвентаризации. Это отдельная подготовка окружения до серверного меню; сам preview не устанавливает пакеты. |

## Первое подключение

1. Создайте VDS Ubuntu 24.04/26.04 amd64; откройте web/VNC-консоль и получите root-пароль либо заранее добавьте публичный ключ через панель.
2. Сравните показанный SSH fingerprint с `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` в консоли. Мастер никогда не отключает проверку host key. Изменённый ключ автоматически не заменяется: проверьте причину через провайдера.
3. Если root-парольный SSH запрещён, выберите Q17=`console`. Команда добавляет публичный ключ, не копирует приватный. На серверах с sudo-only доступом получите root-доступ через консоль; неявная настройка sudo не выполняется.
4. При собственной VPN на компьютере убедитесь, что административный маршрут достигает VDS: доступ к IP самого входа через его прокси намеренно запрещён.

## Повтор, прерывание, откат

На компьютере не сохраняются комплект программы, deployment.json или созданные клиентские пароли. На **входной VPS**: `/var/lib/empire-vpn/ID/deployment.json` и `clients.json` в каталоге0700, файлы0600. Последний файл — готовый экспорт для будущего переноса. При необходимости пользователь забирает его отдельно по SCP в защищённую папку вне Git. Не выводите содержимое в терминал/отчёт. Серверные WG-ключи генерируются на соответствующих VDS и не скачиваются.

На VDS: `/var/lib/empire-vpn/ID`0700 содержит ключ, метаданные транзакции и отдельный root-only каталог `transactions/TX/backups` с точечными резервными копиями0600. Содержимое конфигураций с секретами не включается в журнал: в нём только ссылки на копии. Файлы `/etc/empire-vpn/ID`, dedicated nft table и systemd units принадлежат конкретному ID. Изменённые извне или неизвестные файлы автоматически не перезаписываются. При неизменном повторе службы не перезапускаются. Установка зависимостей и сборка идут до сетевой транзакции; установленные пакеты, сборочный кэш, служебный пользователь и WG-ключ при откате остаются, чтобы повтор не менял секреты.

Перед изменением сети сохраняются точечные копии и ставится постоянный systemd timer на30мин. `Ctrl+C`, потеря компьютера/SSH или ошибка применения оставляют таймер; обычная ошибка вызывает немедленный откат. Сервер возвращает код42 после применения; запускающий код открывает НОВЫЕ ключевые SSH-сессии к обеим нодам и лишь затем вызывает серверную финализацию. Фиксация разрешена после этих сессий и обязательных проверок. Нет распределённой атомарности между двумя VDS: при обрыве терминала/координатора одна уже может быть зафиксирована, а другая откачена таймером. У обеих сохранён последний журнал; восстановите доступ и выполните `rollback` обеих либо продолжайте только после сверки состояния.

`rollback` отменяет последнюю транзакцию обеих ролей, восстанавливает только перечисленные файлы/службы и собственную nft table, не загружает полный старый host ruleset. В консоли конкретной VDS можно выполнить `python3 /var/lib/empire-vpn/ID/transactions/TX/remote.py rollback-local /var/lib/empire-vpn/ID/transactions/TX`. Старый журнал не может отменить более новую транзакцию. При чужом изменении файлов откат останавливается и требует ручной сверки, вместо уничтожения чужих изменений.

Legacy-выход: добавляется отдельный WG-интерфейс, прежняя пара ключей используется повторно; старый туннель остаётся. В `personal_host` добавляются маркированные разрешения, а его постоянный `/etc/nftables.conf` точечно дополняется; глобальная перезагрузка nft ruleset не выполняется. Legacy-вход при замене выхода: сохраняются собственный WG-ключ, службы, credentials и реле; обновляются peer/endpoint и известные ACL. При managed-замене с тем же ID WG-соединение переключается и возможен краткий перерыв.

## Проверки после установки

- `preview`: чтение SSH/платформы/маршрутов и перечень файлов, без постоянной записи. Для первого принятия host key нужен обычный мастер, preview его не добавляет. Локальный offline-preview в `client.py` предназначен только для разработческих тестов; пользовательский preview выполняется на VPS. Временные SSH-туннели/RPC — транспорт сеанса, постоянные настройки они не меняют.
- `verify`: временный клиент sing-box на входе, доверенный TLS, сайт, TCP HTTPS и UoT v2 DNS/STUN через Naive. Целевой служебный порт UoT — **0**. Проверяются запрет private UDP/IPv6 и новые SSH.
- `acceptance`: сначала verify; после отдельного `FAIL-CLOSED` WG входа отключается, проверяется отказ TCP/DNS/IPv6, затем восстановление. Есть отдельный 120-секундный таймер подъёма WG. Это выборочные активные проверки, не полный packet capture.
- `reboot-test`: отдельное `REBOOT`, по очереди выход/вход; новые bootID, отсутствие ordering-cycle в журнале, повтор verify. Применяйте только в согласованном окне работ.

Для любого повторного действия снова выполните ту же команду README: Q03/Q05/Q09 подключают узлы, затем Q00 выбирает действие и Q02 — сохранённый ID. Ручное редактирование JSON не требуется.

Первое реальное получение и будущее продление ACME требуют доступности DNS и TCP80/443. Старое TLS-хранилище не требуется. Встроенный минимальный сайт устанавливается автоматически; перенос прежнего сайта и панель пользователей в v1 не входят.

## Закреплённые источники

`versions.json`: Go1.27.3, Caddy2.11.9, xcaddy0.4.7, конкретный commit forwardproxy, sing-box1.14.4. Go и sing-box проверяются по закреплённому SHA256. Caddy собирается из официальных Go-модулей с GOSUMDB; транзитивные зависимости определяются их go.mod. Пакеты Ubuntu берутся из подписанных репозиториев ОС: их версии не заморожены, пакетная установка не откатывается. Новая версия компонентов требует отдельного выпуска установщика.

Официальные источники: [Go](https://go.dev/dl/), [Caddy](https://github.com/caddyserver/caddy), [xcaddy](https://github.com/caddyserver/xcaddy), [Naive forwardproxy](https://github.com/klzgrad/forwardproxy), [sing-box1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4), [HTTP inbound](https://sing-box.sagernet.org/configuration/inbound/http/), [Python](https://www.python.org/downloads/release/python-31210/).
