# VPN + VPN Control — v0.4.0-rc4

**rc4 — исправление fresh writer cutover:** согласованы свежий Unix admin socket, snapshot и откат; окружение Caddy validator совпадает с установленными службами. Границы проверок фиксируются в отчёте выпуска; локальный panel-gate не заменяет полную установку двух VDS. Полная установка двух VDS (F3) остаётся отдельной фактической проверкой.

**rc3 исправляет остановку настройки панели после ввода owner в rc2:** общий lock создаётся с правами0600, существующий0644 нормализуется без замены файла. Ошибки панели показывают безопасное название этапа. Runtime/core и реквизиты не менялись. Реальная установка двух VDS (F3) остаётся открытой до повторной проверки владельца; rc2 на этой проверке завершился ошибкой. Агент ноды не очищает и не переустанавливает.

Одна команда Windows загружает закреплённый GitHub bootstrap и запускает общий SSH-мастер. Оба сервера автоматически загружают пакет; bootstrap проверяет встроенный SHA256. Локальные Python/Git и ручная передача bundle не нужны.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "iex (irm 'https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.4.0-rc4/bootstrap/windows.ps1')"
```

**Реальную установку на очищенных нодах проверяет владелец; F3 остаётся открытой.** Агент не имеет разрешения очищать/переустанавливать текущие ноды. Core панели закреплён на чистой release-ревизии `6bfb74bfa891071a5b8e316b23178026edd7d19e`, schema8; отложенные portable/prune WIP не включены в runtime.

## Что будет в панели после установки

- Создание, просмотр, изменение display name, отключение/включение и удаление пользователей; защищённый `master_user`, точный регистр логинов.
- Скачивание персональных профилей с логином и версией клиента в имени файла.
- Отдельный владелец панели: имя и срок сессии в шапке, смена пароля в **System** с отзывом всех owner-сессий.
- **System**: измеренные CPU%, RAM, load average, свободное место, объём DB/WAL/SHM и сетевые RX/TX-счётчики с источником и временем. Просроченные данные помечаются stale; есть обновление по кнопке.
- **Overview**: даты сохранённых аудитов и резервных копий. Отсутствующие сведения показываются как Not recorded/Not measured; exit health не выводится из локальных ресурсов.

Текущий выпуск включает принятые части W9U и W10U03. Live exit health, exit-local audit, история/пики ресурсов и portable migration остаются вне этого выпуска.

## Перед очисткой

1. Получите актуальный экспорт из действующего реестра панели. Старый `clients.json` установщика может быть неактуален после изменений через панель.
2. Сохраните файл вне Git/публичной папки и сделайте отдельную защищённую копию. Проверьте формат `empire-vpn-clients`, `schema_version: 1`, список `clients` с `username/password`, наличие `master_user` с прежним паролем. Имя `empire-vpn-clients-v1.json` условное — Q13 принимает выбранный локальный путь.
3. Сверьте список с текущими активными пользователями и прежними профилями. JSON v1 не переносит статусы: все включённые записи станут активными. Не включайте отключённые/отозванные записи из устаревшей копии. Case-only коллизии вроде `Alex`/`alex` требуют отдельного review существующего legacy-инвентаризатора; не очищайте ноды, пока файл не признан пригодным.
4. Только после подтверждения актуального экспорта самостоятельно очищайте ноды. После переустановки сверьте новые SSH host fingerprints с консолью провайдера; не отключайте host-key checking.

## Один проход мастера

- Выберите `new` → `fresh`, укажите обе подготовленные Ubuntu 24.04/26.04 amd64 ноды и прежние параметры подключения (домен/порт/адреса), если хотите использовать старые профили. Q16 — `ready`: DNS уже указывает на вход, HTTPS должен пройти проверку.
- В Q13 выберите локальный JSON-файл. Существующий импорт сохраняет логины и пароли, включая переданный `master_user`; Q14 не создаёт замену импортированным реквизитам. Изменять файл/публиковать пароли не нужно.
- После VPN commit мастер инициализирует панель из того же установленного реестра клиентов через существующий G3/MIG05. На P01–P03 задайте отдельные owner login/password панели, не совпадающие с VPN `master_user`.
- Сохраните VPN-профиль (Q24) и публичный Panel CA. Сверьте fingerprint в проверенном SSH-сеансе и явно доверьте CA на клиенте. Не отключайте TLS verification.
- Подключитесь прежним VPN-профилем, откройте `https://panel.home.arpa`, войдите владельцем. Убедитесь, что импортированные пользователи видны, создайте тестового пользователя, скачайте и проверьте его профиль.

Если прежний профиль не содержит приватного DNS для `panel.home.arpa`, используйте сохранённый на Q24 профиль: реквизиты импортированного пользователя сохраняются, а доступ к панели включён в его DNS/routing.

Локальные проверки пакета/controller/render/bootstrap не заменяют F3. При ошибке панели уже committed VPN не откатывается: сохраните сообщения и migration/journal, не сбрасывайте ключи и не запускайте повторную очистку.

Ограничения: только fresh, не upgrade/replace/portable; существующие registry/key/TLS/units панели вызывают отказ. Leaf-сертификат private panel действует 365 дней, автоматическое продление пока отсутствует. Публикация сайта после fresh panel отложена для сохранения worker site-baseline.

macOS-вход сохранён: `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.4.0-rc4/bootstrap/macos.sh)"`. Настоящая macOS-проверка не выполнена. Локальный `-BundlePath` остаётся дополнительным способом доставки. Ниже сохранена история VPN-only v0.3.6, а не команда нового выпуска.

# Персональная VPN — v0.3.6

**Установщик работает на VPS; диалог — в вашем терминале через SSH.** На компьютер не скачиваются комплект, шаблоны или сборки; локальный Python и Git не нужны. Короткий запускающий текст выполняется в памяти штатной оболочки. Обе VPS сами получают закреплённый комплект из Git, проверяют SHA256 и устанавливают компоненты из официальных источников.

Нужны две VDS **Ubuntu 24.04/26.04 amd64**, первоначальный root-доступ/консоли провайдера и домен. Поддерживаются новая пара, замена входа и замена выхода. Архив старого сервера не требуется. Приватные SSH-ключи остаются на компьютере; ssh-agent на VPS не перенаправляется.

Откройте обычный PowerShell под своей учётной записью. Windows отдельно запросит повышение прав при установке OpenSSH Client или запуске системной службы ssh-agent.

**Windows10/11**, Windows PowerShell5.1 или PowerShell7 — одна команда:

```powershell
& ([scriptblock]::Create((Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.3.6/bootstrap/windows.ps1').Content))
```

**macOS11+**, Terminal с zsh или bash — одна команда, без PowerShell:

```sh
/bin/bash -c 'set -e; code=$(curl -fsSL --proto "=https" https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.3.6/bootstrap/macos.sh); /bin/bash -c "$code"'
```

### Повторный запуск сразу в меню Q00

Если обе VDS уже настроены, используйте те же SSH-алиасы и ID установки. В примерах это `hh-entry`, `hh-exit` и `nh1`. Команда использует ключи и ProxyJump из пользовательского SSH-конфига. Для защищённого ключа предварительно разблокируйте его в ssh-agent. Мастер проверяет доступ и сохранённые роли обеих нод, затем открывает меню. Экспорт клиентов повторно не нужен.

**Windows PowerShell**

```powershell
& ([scriptblock]::Create((Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.3.6/bootstrap/windows.ps1').Content)) -EntryAlias hh-entry -ExitAlias hh-exit -DeploymentId nh1
```

**macOS, zsh или bash**

```sh
/bin/bash -c 'set -e; code=$(curl -fsSL --proto "=https" https://raw.githubusercontent.com/alxkirshenbaum-hue/empire451f/v0.3.6/bootstrap/macos.sh); /bin/bash -c "$code" -- --resume "$@"' -- hh-entry hh-exit nh1
```

После успешного входа по IP мастер предложит сохранить короткое SSH-имя на этом компьютере (Q23). Например, имя `nnh1` позволит подключаться командой `ssh nnh1`. Enter пропускает этот шаг.

Сначала укажите SSH входа/выхода и выберите/создайте ключ. Windows при необходимости предложит системный OpenSSH Client. Затем серверный мастер в том же окне спросит режим, адреса и домен, покажет конкретные изменения и запросит `APPLY`. Непонятный вопрос найдите по **Qxx** в [подробной инструкции](GUIDE.md).

Повторные проверки и откат запускаются **той же командой**: в серверном меню Q00 выберите `apply-saved`, `preview`, `verify`, `rollback`, `acceptance` или `reboot-test` и прежний ID. Редактировать конфигурационные файлы вручную не требуется. DNS установщик не переключает.
