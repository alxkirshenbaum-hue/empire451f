# Проверки v0.3.0 — 10 ноября 2026

Среда разработки — Windows, Python3.12 только как инструмент разработчика, Windows PowerShell5.1 и PowerShell7. Пользовательский запуск v0.3.0 локального Python не использует. Настоящего macOS и Linux/systemd/netns окружения нет. Рабочие VDS и DNS не изменялись.

Локальный итог: **39 PASS, 1 SKIP** (настоящий macOS). Нативный запуск с процессом-заглушкой SSH успешно выполнен в обеих поддерживаемых оболочках Windows, включая передачу настоящей закодированной команды серверного загрузчика через разбор аргументов Windows.

Проверяются: генерация обеих ролей с тестовыми адресами; HTTP CONNECT/UoT и fail-closed; systemd socket dependencies; непривилегированные сервисы; импорт/экранирование credentials; валидация ввода; запрет защищённых адресов; неизменный повтор; остановка при чужих файлах; preview без записи/ключей; раздельные SSH-ошибки; исправление ответа; checksum; отсутствие секретов в ошибках/журнале; сохранение WG-ключа; устаревший откат.

Аварийное применение проверяется с настоящими временными файлами и подменёнными Linux-командами: исходный файл восстанавливается, созданный удаляется, pending очищается. Секретное содержимое лежит в отдельной резервной копии, а не в метаданных журнала. Legacy-выход сохраняет старые правила/ключ и получает маркированные дополнения.

Новая транспортная архитектура отдельно проверяет: авторизацию loopback-RPC, отказ без токена, штатное завершение, отсутствие клиентских паролей в запросах к выходу. Серверный координатор возвращает управление компьютеру после apply и **не фиксирует транзакцию**, пока запускающий код не откроет новые SSH-сессии.

В настоящих PowerShell5.1 и7 проверяются синтаксис, генерация SSH-config, пути с пробелами и весь запуск с процессом-заглушкой SSH: серверный диалог, возврат42, новые проверки обеих SSH-сессий, затем finalize. Заглушка не устанавливает VPN и не обращается к VDS. Комплект исходников скачивается серверным загрузчиком, а не Windows-загрузчиком.

Реальный macOS-тест помечен SKIP. Не испытаны: реальный PTY/два SSH-туннеля к VDS; установка на чистую Ubuntu 24.04/26.04; nft/systemd validation в Linux; сборка Caddy на новой VDS; применение legacy-adapter; фактические TCP/UoT/отказ WG/reboot через новый установщик; получение/продление ACME. Первая практическая приёмка — по MIGRATION_TEST.md с Windows, после отдельного согласования изменений.
