# Единый мастер установки · уточнение владельца 15.11.2026

Это актуальный контракт W9.5, приоритетный над прежними формулировками F4 и локального candidate в PRIORITY_FRESH_INSTALL/README. Реализуется только fresh — новая пара VPN+панель.

## Пользовательский вход

Владелец копирует одну команду из инструкции GitHub в PowerShell. На его компьютере заранее нет файлов установщика. Команда сама загружает bootstrap и соответствующий пакет, проверяет контрольную сумму и запускает существующий SSH-мастер Q00–QNN. Скачивание ZIP вручную, распаковка, выбор локальной папки и BundlePath допустимы для разработки, но не закрывают пользовательскую приёмку.

Q00 и последующие вопросы сохраняют текущую модель мастера. После успешного fresh владелец получает работающие VPN, приватную панель, настроенные API/worker и инструкции первого входа. Ввод отдельного owner и получение доверенного CA остаются частью того же прохода мастера. Секреты не включаются в команду или логи.

## Сценарии общего мастера

| ID | Путь | Текущий объём |
|---|---|---|
| M1 | Новая пара → установить VPN и панель | Реализовать сейчас |
| M2 | Существующая пара без панели → доустановить панель | DEFERRED_BY_OWNER, сейчас не реализовывать |
| M3 | Существующая пара с панелью → обновить её | DEFERRED_BY_OWNER, сейчас не реализовывать |

M2/M3 в будущем запускаются из той же команды через подходящий выбор существующей установки. Мастер определяет состояние, показывает изменения/влияние и запрашивает подтверждение. Пользователи, пароли, профили и настройки сохраняются. Отдельная ручная процедура не будет критерием готовности этих сценариев. Сейчас достаточно отразить ограничения в инструкции/выборе и корректно отказать неподдерживаемому сценарию. Существующие рабочие возможности VPN-only мастера сохраняются по его контракту.

## Приёмка текущих F1–F4

- F1 — единый пакет проверенных компонентов и согласованные версии/контрольные суммы.
- F2 — существующий fresh-мастер устанавливает панель за один проход вместе с VPN; это реализованный путь, а не только набор команд для ручного deploy.
- F3 — на разрешённой новой паре команда из инструкции → вопросы мастера → owner login через VPN → create → download → подключение TCP/UoT. Стендовые и mock PASS сохраняются с их границами. При отсутствии пары фиксировать только F3 BLOCKED, с точной недостающей проверкой.
- F4 — опубликованная команда проверена в пустой локальной папке: автоматически скачаны нужные bootstrap/пакет, проверен SHA, мастер стартует. README/GUIDE содержат эту команду и первый вход. Локальный ZIP и mocks доставки — промежуточные результаты. Проверка команды заканчивается до изменений VDS, поэтому отсутствие новой пары само по себе не блокирует её выполнение.

Для fresh-кандидата допускается явно обозначенный prerelease. Опубликованные команды должны ссылаться на согласованную версию, прежний стабильный выпуск остаётся доступен. Предпочитать существующий release/bootstrap процесс. macOS-вход сохраняется; доказанность запуска на настоящем macOS отражается отдельно, без ложного PASS.

Разрешение на реализацию и локальные проверки дано. Публикация релиза и изменения реальных VDS — отдельные области: при отсутствии действующего разрешения подготовить точный артефакт/команду и запросить разрешение только на нужное действие. Не приписывать F4 PASS до публикации и проверки команды.

Portable export/import, upgrade M2/M3, расширенные W8/W9/E тесты сейчас не являются предпосылками. Существующие релевантные PASS использовать повторно. Общий W9.5 целиком остаётся частичным после приёмки fresh, поскольку M2/M3 отложены.
