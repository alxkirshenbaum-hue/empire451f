# W9.1 · общий установщик VPN и панели

Согласовано 14.11.2026. Статус реализации 0/6, G9.1 открыт. W9 завершает приёмку компонентов панели, G9.1 завершает готовность общего выпуска E1 для пользователя. W10 и последующая нумерация сохраняются. Разработку W8/W9 продолжать по текущему первому открытому пункту; реализация W9.1 следует за ними.

## Цель и зависимости

Команда из README/GUIDE устанавливает новую VPN-пару вместе с приватной панелью. Для существующей пары та же точка входа предлагает подключение или обновление панели с сохранением пользователей, паролей и существующих профилей. В nh1 уже установленная панель распознаётся как существующая установка.

Перед реализацией сверить актуальные build_release.py, bootstrap, controller.py, remote.py, версии и результаты G3–G9. Зафиксировать контракт интеграции с принятой версией панели. Переиспользовать её миграции, общий lock, runtime policy, проверку применения, backup/restore и возврат установщику. Собрать минимальный diff по существующим входам. Новые постоянные службы или журналы вводить только при доказанной необходимости.

## 1. Состав и совместимость выпуска

- [ ] Определить и включить в release все runtime-компоненты панели: Go-бинарники, Python helpers, UI, миграции, unit-файлы и шаблоны политики. Сборочные инструменты остаются частью подготовки выпуска.
- Зафиксировать версии VPN-компонентов, панели, схемы БД, поддерживаемых ОС/архитектур VDS и клиентских SFA. Поддерживаемые цели выводить из действующего установщика.
- Сборка использует явный список файлов, воспроизводимые исходники и проверяемые контрольные суммы. Проверить отсутствие секретов, реальных профилей, снимков и тестовых данных в артефактах.
- Bootstrap Windows/macOS получает согласованный набор версии/пакета/контрольных сумм. Ошибка проверки или неподдерживаемая версия останавливает установку до изменения runtime.
- Результат — спецификация артефакта и собранный кандидат общего пакета.

## 2. Чистая установка

- [ ] Встроить развёртывание панели в штатный мастер новой пары.
- После готовности VPN подготовить runtime-идентичности, приватные каталоги и сокеты, реестр/vault, политику worker, API/frontend, systemd и доступ panel.home.arpa. Порядок взять из принятого runtime, включая старт после reboot.
- Создать независимого владельца панели через защищённый bootstrap, выдать инструкции по доверенному TLS и первому входу. Секреты вводятся закрыто и не попадают в аргументы команд/логи.
- Мастер должен объяснить дальнейшие действия при незавершённой настройке панели и показывать фактический статус VPN и панели.
- Результат — из чистой поддерживаемой пары можно войти через VPN, создать пользователя и скачать профиль.

## 3. Подключение и обновление существующей пары

- [ ] В существующей ветке Q00 определить режим по фактическим manifest/schema/owner/runtime.
- Согласовать план изменения и влияние на соединения. Подготовить проверенный backup до изменения.
- Для legacy-пары использовать принятую сверку четырёх источников, импорт и передачу writer под общим lock. Сохранить Caddy-only записи, регистр, master_user и прежние реквизиты.
- Для пары с панелью выполнить совместимое обновление файлов и схемы. Повтор на той же версии должен корректно определить результат, сохранив владельца и пользователей.
- Проверить существующие профили побайтно, старое подключение и новое создание/выдачу. Если старому профилю требуется настройка доступа к панели, объяснить владельцу действие с учётом запрета молчаливой перезаписи.
- Результат — оба режима доступны через документированную команду без переустановки VPN.

## 4. Прерывание, повтор и возврат

- [ ] Определить точки восстановления для скачивания/проверки пакета, файлов, миграции, runtime и передачи writer, сопоставив каждую с существующей процедурой.
- Сбои с одинаковым наблюдаемым состоянием обрабатывать общей сверкой. Повтор сохраняет прежние секреты и продолжает только доказуемое состояние.
- При неизвестном результате показать оператору конкретную SSH-процедуру и заблокировать конфликтующие записи.
- Возврат после новых пользовательских операций сохраняет актуальный реестр и действующие реквизиты. Для несовместимого downgrade определить поддерживаемый путь восстановления до обновления.
- Результат — воспроизводимая репетиция сбоя и повторного запуска, возврат до/после мутации через уже принятые механизмы.

## 5. Инструкции и публикация

- [ ] Обновить README/GUIDE, команды Windows/macOS, версию, release notes и инструкцию обновления.
- Включить новый пакет в обычную сборку и релизный процесс. Проверить, что опубликованные команды обращаются к нужной версии и проверяют правильные контрольные суммы.
- Описать первый вход, доступ через VPN, роль владельца, скачивание профиля, повтор прерванного мастера и восстановление через SSH.
- Результат — кандидат опубликованных инструкций и артефактов, затем фактический релиз после приёмки.

## 6. G9.1 — приёмка общего выпуска

- [ ] Принять точную опубликованную версию и заполнить матрицу ниже.

| Сценарий | Обязательное наблюдение |
|---|---|
| Чистая пара, Windows | Команда из инструкции → VPN → приватная панель → owner → create/download → подключение |
| Чистая пара, macOS | Та же цепочка через настоящий macOS; фиксировать ОС и версию |
| Legacy-пара | Импорт/передача writer, прежние профили и подключения, новый пользователь |
| Пара с принятой панелью | Обновление и повтор на той же версии, сохранение данных и owner |
| Прерванное изменение | Общая сверка, безопасный повтор или предусмотренный возврат |
| Границы безопасности | Приватность панели/сокетов, новые SSH обеих нод, fail-closed по затронутым участкам |
| Старт и ресурсы | Зависимости после reboot, дополнительный диск с пакетом/staging/backup в бюджете W8 |

Для каждой строки записать revision, артефакт/hash, среду, команду, результат и границы. Стабильные результаты G3–G9 переиспользовать, повторяя проверки затронутых компонентов. Полный путь через опубликованную команду обязателен. Рабочие изменения nh1, restart и испытания с отключениями требуют согласования в своей области.

G9.1 принимается после прохождения матрицы и проверки опубликованной инструкции. Незавершённые сценарии остаются открытыми. Приёмка W9 продолжает учитываться как приёмка компонентов; готовность общего E1 включает G9.1.
