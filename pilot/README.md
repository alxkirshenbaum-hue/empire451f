# Пилот закрытого доступа к панели

Область — отдельный временный опыт на управляемом входе nh1. Обычный установщик его не выполняет. Запуск nh1-route.sh одноразовый. Для повторного опыта сначала сверить остатки и состояние служб.

1. Убедиться в доступности нового SSH к обеим нодам, действующем VPN и отсутствии незавершённой транзакции установщика. Работать под его общим lock.
2. В namespace naive поднять статический ответ HTTPS с отдельной идентичностью systemd и отдельным случайным паролем. Привязать его только к 127.0.0.1:18650. Приватный ключ временного CA удалить сразу после подписи листового сертификата. Сертификат и профиль передать на устройство через доверенный канал. После опыта удалить CA с устройства.
3. Проверить кандидата sing-box. Только для TCP 443 с HTTP inbound uot имя panel.home.arpa и тестовый адрес 192.0.2.119 ведут на фиксированный локальный сокет. Общие правила выходного VPN остаются в исходной конфигурации. Пилотный профиль SFA содержит локальную запись DNS для одного имени.
4. До переключения поставить таймер отката. Временный systemd drop-in использует копию текущего конфига в /run. Перезапуск sing-box затрагивает также Caddy через systemd. До завершения опыта отложить другие изменения серверного конфига sing-box.
5. Проверить новые SSH к обеим нодам, вход владельца, запрос без авторизации, внешний TLS, сайт, обычный исходящий TCP/UoT. Останавливать защитный таймер только после успешных проверок.
6. На телефоне использовать отдельную копию профиля. Проверить доверие браузера без пропуска предупреждений, вход и недоступность с отключённым VPN. Состояние WG ради этого опыта не менять.

Ручной сетевой откат на входе: `bash /run/nh1-panel-pilot/rollback.sh`. Он снимает временную конфигурацию, перезапускает штатный sing-box и останавливает тестовый HTTPS-сервис. При перезагрузке /run очищается, штатная конфигурация запускается автоматически. Материалы передачи в защищённом каталоге root сохраняются до отдельной уборки.

## Проверка 12 ноября 2026

Проверены запросы через реальный Naive-клиент по домену и тестовому IP с проверкой имени сертификата. В обоих случаях получены HTTP 401 без пароля и HTTP 200 с паролем владельца. При прямом обращении с Windows на публичный IP с SNI panel.home.arpa TLS-соединение отклонено. Штатная verify.py подтвердила TCP и STUN через ожидаемый выход, DNS/UoT, сайт с доверенным TLS и блокировку частного UDP и IPv6. После переключения открылись новые SSH-сессии к обеим нодам.

Владелец проверил пилот на OnePlus 12. С включённым VPN браузер открыл `https://panel.home.arpa` без предупреждения о сертификате и показал `VPN Control: private pilot OK`. С выключенным VPN браузер сообщил `DNS_PROBE_FINISHED_NXDOMAIN`. В сочетании с отдельной проверкой прямого подключения по публичному IP это подтверждает целевой сценарий доступа владельца.

На OnePlus отмена ввода логина и пароля панели дала HTTP 401. В отдельной проверке Naive-клиент подключился под обычной VPN-учётной записью и запросил страницу по HTTPS с проверкой сертификата. Без реквизитов панели получен HTTP 401. Требование T-049 подтверждено для тестовой страницы. Когда появится административный API, проверку следует повторить на его защищённых методах.

G0a подтверждён частично. Открытым остаётся T-051 — проверка изоляции при отказе WireGuard с установленным пилотом.
