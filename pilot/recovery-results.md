# W1. Восстановление с внешним ключом

12 ноября 2026 проведён сквозной опыт с синтетическими учётными данными. На компьютере владельца процесс создал временный 3072-битный RSA-ключ в памяти. Входная нода получила только открытый ключ по SSH. Временный процесс с PrivateNetwork, DynamicUser и закрытым доступом к рабочим файлам создал два поколения данных до и после отзыва доступа. Каждое содержит SQLite, ключ хранилища, Caddy auth и профиль на основе шаблона проекта. У обоих поколений одни исходные пользователи и пароли.

Контейнер опыта использует компактную сериализацию JWE, RSA-OAEP-256 и A256GCM. Контрольные значения получены по доверенному SSH-каналу. Открытый ключ получателя позволяет любому зашифровать новый контейнер: в будущей эксплуатации происхождение резервной копии нужно проверять отдельно, например по независимо сохранённому доверенному манифесту. Формат опыта отдельный; существующий архив инфраструктуры v1 в испытании не использовался.

| Проверка | Результат |
|---|---|
| Расшифровка на компьютере владельца, SQLite integrity_check, расшифровка credentials, сверка профиля и auth | Восстановлены согласованные данные поколения 2 в новом временном каталоге |
| Другой приватный ключ, изменённый контейнер, повреждённый тег с пересчитанным внешним SHA256 | Все три попытки отклонены, восстановленные ранее файлы сохранили контрольные суммы |
| Подлинная более ранняя копия, в которой ещё разрешён отозванный пользователь | При ожидаемом поколении 2 восстановление поколения 1 отклонено |
| Восстановление в уже заполненный каталог | Отклонено до публикации |
| Проверка восстановленного профиля установленным sing-box | Конфигурация прошла check |
| Отдельный экземпляр Caddy/forward_proxy, восстановленный auth и клиент Naive | Активный пользователь успешно передал TCP-данные до и после отрицательной проверки; отозванная учётка доступа не получила |

Для последнего опыта во второй изолированный процесс передавались только синтетические материалы. У клиентского outbound заменены адрес локального стенда и доверенный тестовый сертификат. Приложение Android, полная действующая база и восстановление ОС в проверку не входили. Пара ключей владельца жила один запуск. Производственного ключа или нового экспорта реальных пользователей этот опыт не создаёт.

Драйвер запускается из Windows через Python с cryptography и SSH-алиасом hh-entry: `python -B pilot/recovery_rehearsal.py`. Исполнение создаёт только временные тестовые данные. Это ограниченный по объёму эксперимент в памяти. Для промышленного контейнера нужны потоковая работа, пределы размеров, независимая проверка происхождения и согласованное хранение приватного ключа вне VDS. Связанные данные AEAD в опыте используют точный логин вместо фиктивного UUID; модуль W2 связывает шифротекст со стабильным ID пользователя и версиями секрета и ключа.
