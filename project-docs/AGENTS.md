# Правила CodexVPN

- Начинай с CURRENT.md и нужной задачи PLAN.md. PLAN_GENERAL.md — карта этапов. Если запрос относится к development-optimization/, начинай с его CURRENT.md; VPN-очередь автоматически не продолжай.
- PLAN содержит только активные задачи и приёмку. Сложные спецификации — plans/<task>.md; реализованное устройство — ARCHITECTURE_TECH.md и ARCHITECTURE_UX.md. История и старые статусы — archive/, читать по конкретной ссылке. Не загружай все уровни при старте.
- Пиши кратко по-русски: строка прогресса текущего этапа, результат, проверки, ограничения и следующий шаг. Считай только целые критерии принятого этапа; подшаги отдельно. U/E и fresh/upgrade не объединяй в общий PASS.
- Сначала чтение. Серверная установка ПО, firewall/маршруты/SSH/интерфейсы/MTU, restart/reboot, удаление и deploy требуют действующего согласования для конкретной среды и действия. Выполненное историческое согласование не разрешает новый повтор; уже данное действующее согласование повторно не запрашивай.
- Резерв 193.233.22.78 не изменять. Существующие клиентские профили и точные credentials/case/status/master protection сохранять; изменения только в явно согласованной области.
- Управлять с Windows по SSH; Codex CLI на VPS без необходимости не устанавливать. Доступность проверять экспериментально. Не отключать host-key checking; не переносить приватные SSH-ключи на VPS.
- Перед сетевыми изменениями подготовить проверяемый откат и административный доступ; после проверить НОВЫЕ SSH-сессии. Default route хостов и SSH не направлять через WG.
- Обязателен fail-closed для проксируемого трафика, DNS и IPv6. Caddy/sing-box изолированы в namespace, непривилегированны, без CAP_NET_ADMIN и доступа к сети хоста. SOCKS upstream для UoT не использовать: служебный порт 0 требует HTTP CONNECT.
- Секреты/приватные ключи/пароли/токены не сохранять в проект/Git/отчёты; не печатать конфиги с секретами и wg showconf/dump. Разрешённые приватные пользовательские экспорты хранить вне Git/проекта, не выводить credentials.
- Старые deploy-network/deploy/switch/publish-скрипты повторно не запускать. test-naive.py/test-isolation.sh меняют WG и не являются read-only диагностикой; новые отказные тесты требуют согласования. observe-vpn.py читает состояние и завершится через 30 минут.
- Не повторять подтверждённые deploy/owner login/fresh, не возобновлять отложенный BL-009/portable/upgrade и старое стендовое debugging автоматически. Использовать релевантные PASS только в прежней области; текущий запрос имеет приоритет.
- Объединять связанные правки и запускать целевые проверки; полный требуемый набор — перед приёмкой этапа. До/после переключения рабочей пары соблюдать порядок её спецификации. Независимая проверка обязательна для security-critical/destructive изменений.
- Не создавать/перестраивать стенд ради удобства вывода или повторения уже принятого сценария. При неизвестном состоянии явно писать unknown/не проверено; не восстанавливать факт из одного старого заголовка.
- Поиск начинать с известных путей; worktrees, .panel-domain-build, сборки, зависимости и archive исключать, пока они не нужны. Проверять фактическую рабочую папку shell; при несовпадении применять абсолютные пути.
- Изменения правил/контекстной структуры фиксировать новой версией в development-optimization/versions до применения; замеры связывать с manifest. Сборщик пока прототип: не обещать автоматический учёт и не оценивать токены на глаз.
