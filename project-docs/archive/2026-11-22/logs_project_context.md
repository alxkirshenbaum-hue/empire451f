## Техническое направление

Кандидат: Caddy с naive-веткой klzgrad/forwardproxy, HTTPS с доменом, сначала HTTP/2 TCP 443. Межсерверный транспорт — обычный WireGuard при подтверждённой UDP-связности. SSH-доступность не доказывает работоспособность WireGuard. Если UDP недоступен, отдельно оценить транспорт по TLS/TCP с учётом TCP-over-TCP.

Предпочтительно изолировать прокси в network namespace: ответы клиентам идут через вход, новые соединения к назначениям и DNS — только через WireGuard. Требуются согласованные policy routing/маркировка и независимые firewall-запреты обхода туннеля, включая IPv6. Простого default route через wg недостаточно. SSH и служебный HTTPS/ACME требуют отдельного продуманного пути; исключения не должны разрешать прямые соединения прокси к произвольным адресам. На выходе forwarding и NAT только для выделенной подсети, без нарушения Xray/3x-ui.

Официальная документация sing-box: naive outbound с 1.13.0, Android поддерживается. Это не подтверждает установленную сборку SFA: нужны версия приложения/ядра и тест импорта отдельного профиля. Hiddify официально заявляет Naive; установленную сборку и сохранение split routing также нужно проверить до развёртывания. UDP-приложения/QUIC нельзя считать поддержанными по факту HTTPS-прокси; отдельно проверить поведение и TCP fallback.

Источники:
- https://sing-box.sagernet.org/configuration/outbound/naive/
- https://github.com/klzgrad/naiveproxy
- https://hiddify.com/app/How-to-install-Hiddify-app/

Риски: блокировка входа/домена/диапазона остаётся возможной; двухузловая схема добавляет задержку и точку отказа; DNS/IPv6/перезапуски могут создать утечку при ошибке правил. Раздельные IP уменьшают раскрытие входа посещаемым сайтам только для корректно проксируемого трафика. Прямой российский трафик намеренно использует IP клиента.

## 2026-11-12 — основной кандидат архитектуры панели для nh1

Панель на входной ноде hh-entry. Целевой адрес https://panel.home.arpa доступен через аутентифицированное подключение SFA/Naive. Публичный HTTPS-вход не должен обслуживать панель даже при ручной подстановке IP и имени. Внутри прокси предполагается отдельный маршрут только к приватной службе панели на TCP 443 с сохранением изоляции и fail-closed для прочего трафика.

Для управления требуется отдельная административная авторизация. Способ входа (например, passkey), внутреннее разрешение имени и доверие устройства к сертификату предстоит выбрать. Статус — кандидат для проектирования. Приёмка должна проверить недоступность извне, доверенный HTTPS через VPN и запрет выдачи профиля обычному пользователю VPN.
