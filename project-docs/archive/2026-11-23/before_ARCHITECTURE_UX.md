# Пользовательские сценарии CodexVPN

## Установка и первый вход

Владелец запускает опубликованную команду GitHub из README, мастер скачивает pinned
bootstrap/пакет, сверяет SHA, задаёт Q00–QNN и по SSH устанавливает новую VPN-пару+панель.
Результат: личный master JSON и приватный URL панели; вход через VPN и системно доверенный
TLS основного VPN-домена со случайным путём. Старый panel.home.arpa/ручной CA из раннего
owner guide — исторический путь, не инструкция текущего rc10.
Реальные адрес/путь/credentials получать из приватного актуального результата, не из архива.
Текущая master binding не означает права управления у каждого VPN-пользователя:
rc10 master login200 / ordinary imported user401.

Fresh F1–F4 принят с границами release report. Полный rc10 Windows wizard прошёл
с -BundlePath; это не доказательство повторного автоматического удалённого ZIP-download.
M2 доустановка и M3 upgrade должны в будущем идти через тот же мастер; сейчас отложены.
Q27 — SSH hardening после handoff; Q28/ProxyJump — отдельные отложенные улучшения.

## Управление пользователями

Owner открывает Users → создаёт exact login с approved template → наблюдает Operations
до Completed и Active → скачивает персональный JSON → импортирует в поддерживаемый SFA
и отдельно проверяет соединение. Повторная выдача не меняет пароль.
Display name изменяем, login сохраняется. Disable/revoke запрещает новые подключения и выдачу,
старые туннели могут жить; Enable возвращает прежние credentials. Delete оставляет tombstone,
login зарезервирован. Обычные операции master_user запрещены.
Имя вложения vpn-<login>-<client>.json, небезопасное legacy-имя заменяется UUID.
После изменения проверяется независимый контрольный пользователь.

## Наблюдаемость и ошибки

System показывает ресурсы с источником/временем, namespace counters не являются
per-user трафиком. Cached observations старше60s — Stale; отсутствие данных — Unknown.
Stored evidence показывает сохранённые audit/backup timestamps, не текущий health выхода
и не доказанный restore. Недоступный/непринятый путь явно обозначать; не обещать полный backup/DR.
Смена admin password требует текущего пароля, отзовёт owner sessions, не меняет VPN credentials/vault.
Повторная операция должна дать прежний результат либо понятный конфликт/безопасный отказ,
а не скрытый overwrite. Подробные действия CLI — [owner guide](installer/controlpanel/OWNER_GUIDE_U.md)
с учётом его исторической версии/старого TLS-входа.

## Границы поддержки

OnePlus12/owner create/download/connect и отдельные SFA версии имеют собственные PASS.
Полные Android DNS/IPv6/RU domain+IP/Per-App/Wi-Fi+mobile/стабильность не доказаны
одним подключением. Старые профили/российские исключения сохранять.
BL-009 Download Manager отложен; не скрывать сбой и не расследовать автоматически.
Owner/manager network allowlist — отдельный дизайн BL-008/W15; независимая admin
авторизация и отказ обычному пользователю обязательны уже сейчас.
Новые user flows требуют критерия приёмки и проверки наблюдаемого результата, не только backend PASS.
